# current-projects.md
## Session-level project state
### A living picture. Loaded when it matters, skipped for one-shots.

> **What this file is:**
> The active constellation of work you're managing right now: open hypotheses, suspended problems, closed branches, and where you most need traction. It changes often. It does not belong in your intent file, which is about how you think, not what you're working on.
>
> **When to load it:**
> At the top of any session where project context matters. Say: "Read my current projects file" and the tutor loads it alongside your intent file before doing anything else.
>
> **When to skip it:**
> One-shots that don't need project continuity. Exploratory sessions where you're following a thread, not managing a deliverable.

---

## SESSION LOADING LOGIC

```
  Always load:        intent.md
  Load when needed:   current-projects.md
  Load for deep work: both, plus whatever project files matter

  One-shot sessions → intent.md only
  Project sessions  → intent.md + current-projects.md
```

## STRUCTURE

### ACTIVE PROJECTS

For each active project, one entry:

```
PROJECT: [Name or brief description]
STATUS:  [Where it stands right now, one sentence]
OPEN:    [Live hypotheses or questions, what's untested]
CLOSED:  [Decisions made, do not revisit without prompting]
STUCK:   [Where traction is needed most]
NEXT:    [The real-world step that leaves the chat window]
```

### SUSPENDED PROBLEMS

Problems opened but not yet resolved, waiting on real-world feedback, data, or time:

```
PROBLEM:    [Description]
SINCE:      [Approximate date or context when it opened]
WAITING ON: [What external input would close or advance it]
```

### CLOSED BRANCHES

Directions that have been tried and rejected. Do not resurrect without being asked:

```
BRANCH:  [What was tried or considered]
CLOSED:  [Why it was closed]
```

### CURRENT PRESSURES

Structural context that should color sessions without being project-specific:

```
[Any constraints, time pressures, organizational dynamics,
 or resource realities that are currently active]
```

## HOW IT IS KEPT SAFE

This file is meant to be overwritten often. Before any rewrite, the tutor copies the current version to `workbook/history/current-projects-<date>-<time>.md`, so an earlier state is always one copy away. If you ever want something back, say so and name the date.

---

## HOW TO BUILD YOUR FIRST ONE

Tell the tutor: "Let's build my current projects file. Ask me what I'm working on." It walks through each section, compiles your answers, reads them back, and saves the file once you confirm every line sounds like you.

Or write it yourself and say: "Save this as my current projects file."

---

## HOW THIS FILE FEEDS THE COURSE

When a module asks you to work on a real project, your Constitution, your six-attack table, your Change Ledger, pull the relevant project from here. The course is designed to work on live problems, not hypotheticals.

As you progress, this file gets more precisely structured: closed branches explicitly named, suspended problems held more cleanly, and the NEXT field becomes a discipline rather than an afterthought. The evolution of this file is itself a readout of your Semantifacturing development.
