## TURN 2 — The three-tier stability model. One diagram.

*(Tutor: Receive their answer. Acknowledge where they land. Then show the model.)*

**Deliver:**

```
THREE-TIER STABILITY MODEL

  ┌──────────────────────────────────┐
  │         PROJECT CORE             │  ← relatively stable
  │  Purpose · Values · Audience     │
  │  Non-negotiables                 │
  └──────────────┬───────────────────┘
                 │
     ┌───────────┴───────────┐
     ▼                       ▼
  WORKING MODEL          EXECUTION
  hypotheses             language
  structure              examples
  mechanisms             format
  strategy               tactics

  revisable              highly revisable
```

> The tiers are not rigid rules — they are awareness. You should be able to feel the difference when the AI makes a tactical suggestion versus when it quietly proposes a strategic shift. Most AI suggestions arrive as improvements. Very few announce themselves as changes to purpose.

**End with:**
> Think about a suggestion the AI — or anyone — has made recently about your project. Which tier did it actually touch? Did it feel like the tier it belonged in, or was it packaged differently?

## TURN 3 — The Alignment Check. Apply it live.

*(Tutor: This is interactive. Don't explain the check — run it on a real example from the learner's project.)*

**Deliver:**

```
THE ALIGNMENT CHECK

When a substantial change appears, ask:
  What level is this actually changing?

  Level 1 — Wording / Phrasing       → change freely
  Level 2 — Tactic / Format          → change freely
  Level 3 — Structure / Sequence     → change with awareness
  Level 4 — Hypothesis / Model       → requires explicit approval
  Level 5 — Strategy                 → requires real justification
  Level 6 — Objective / Values       → requires your full, deliberate decision
```

> The trap: AI suggestions frequently make tactical changes that quietly change strategy, or strategic suggestions that quietly change purpose. They arrive fluently. They do not announce themselves.

**End with:**
> Let's apply this right now. Think of one change your project has made — whether from AI input, a colleague, or your own thinking — over the past month. Run the Alignment Check on it: what level did it actually change?

## TURN 4 — The Change Ledger. Brief, then build it together.

**Deliver:**

```
THE CHANGE LEDGER

Entry format:
  ┌────────────────────────────────────────┐
  │ DATE:                                  │
  │ CHANGE: We changed X to Y             │
  │ SOURCE: AI / customer / data /        │
  │         colleague / personal insight  │
  │ WHY: What justified this update?      │
  │ WHAT REMAINS UNCHANGED:               │
  │   Which invariants still hold?        │
  │ REVERSIBLE? Yes / No / Partly         │
  └────────────────────────────────────────┘
```

> The Source field is the one to watch. If every entry says "AI" — that is a signal. The Semantifacturing loop requires the world to answer back. AI can accelerate your thinking between real-world feedback cycles; it cannot replace them.

**End with:**
> Let's fill in your first three entries together. Think of: one change you've already made during this course, one change you were planning before, and one change you considered but rejected. Which ones come to mind?

## TURN 5 — The Eternal Chat Failure. Direct, brief.

*(Tutor: This is the sharpest failure mode in the course. Deliver it plainly — do not soften it. It is the fifth mode on the card in `reference/failure-modes.md`.)*

**Deliver:**

```
THE ETERNAL CHAT FAILURE

  The user recursively asks AI to critique
  AI's critique of AI's synthesis.

  What it feels like: enormous intellectual progress.
  What it is: a loop that never touches the world.

  The cure:
  ──────────────────────────────────────────
  After every meaningful session with your AI,
  LEAVE THE CONVERSATION.

  → Talk to a colleague
  → Send the email
  → Show the draft
  → Run the experiment
  → Gather real data
  → Encounter resistance
  → Sleep on it
  ──────────────────────────────────────────
  Then come back. The REFINE node runs on
  real-world feedback, not more generation.
```

**End with:**
> When was the last time you had a long AI session that felt very productive — and then nothing happened? What would have needed to be true for something to happen afterward?

## TURN 6 — The Branching Habit (optional but valuable for complex projects).

*(Tutor: Offer this if the learner has a significant ongoing project. Keep it brief.)*

**Deliver:**

```
THE BRANCH HABIT

  When the AI proposes something fundamentally different:

  MAIN PROJECT
       │
  ┌────┴────┐
  ▼         ▼
CURRENT   NEW IDEA
VERSION    BRANCH
  │             │
  │       investigate
  │             │
  └──── compare ┘
         │
   YOUR decision

  Never overwrite the main project directly.
  Branch, investigate, compare, then decide.
```

**End with:**
> Does your project have any "branches" right now — directions you're considering that you haven't committed to? What would it take to investigate one of them without risking the main thread?

*(Tutor: Compile three Change Ledger entries from the conversation, following the shape of `workbook/artifacts/change-ledger.md`. Read them back. Ask: "Do these accurately capture what changed, why, and what stayed fixed?")*

If the Constitution needs updating based on genuine evolution (not drift), the history rule applies to the file being changed: copy `workbook/artifacts/constitution.md` to `workbook/history/constitution-YYYY-MM-DD-HHMM.md`, tell the learner, name what changes and ask, then rewrite it. Add a Ledger entry for that change with `SOURCE: this course`, so the Ledger records its own first use.

> Your Change Ledger is saved. This is a living document — add to it any time your project makes a deliberate change. The Source field is your accountability column.
